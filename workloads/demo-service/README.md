# demo-service

Wave 10. First real workload — a hand-written KubeVela Application that proves the full dev stack end-to-end:

| Capability                | What this touches                                                        |
| ------------------------- | ------------------------------------------------------------------------ |
| cert-manager + step-ca    | `Certificate` from the `step` `StepClusterIssuer` → `demo-service-tls`   |
| KubeVela                  | Renders both `webservice` components (`web`, `tracegen`) and `addons`    |
| Tempo                     | `tracegen` pushes OTLP traces to `tempo.monitoring.svc:4317`             |
| kube-prometheus-stack     | ServiceMonitor on `web` produces `up{namespace="demo-service", ...}`     |
| Sloth                     | `PrometheusServiceLevel` compiles into a multi-window burn-rate rule     |

## Not a chart

`workloads/demo-service/` is a plain-manifest directory, not a helm chart — `skylab-apps` ships `sourceType: directory` for this component so Argo CD syncs the YAML as-is. `charts/` stays reserved for platform wrappers.

## Why `up` for the SLO?

`nginxdemos/hello` doesn't publish Prometheus metrics; the /metrics scrape 404s, so `up=0`. That's deliberate — it gives Sloth a non-trivial error budget to burn in demos without having to instrument a real app. When the first instrumented golden-path service lands, the SLO flips to an RED-style events SLI.
